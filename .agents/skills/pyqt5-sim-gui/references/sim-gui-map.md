# SIM_AutoSystem PyQt5 GUI Map

## Runtime

- Launch: `start_sim_control.cmd`
- Manual launch: `.venv\Scripts\python.exe sim_control_app.py --config config\sim_control_config.json`
- Qt binding: `PyQt5`
- Generated settings dialog: `sim_control/ui_sim_settings_dialog.py` from `sim_control/sim_settings_dialog.ui`

## Main SIM Files

- `sim_control_app.py`: QApplication setup and `SimControlWindow` launch.
- `sim_control/gui.py`: hand-written dialogs, main window logic, signals, settings synchronization.
- `sim_control/preview.py`: latest-frame-wins live preview worker/cache.
- `sim_control/controller.py`: acquisition orchestration.
- `sim_control/adapters.py`: camera, SLM, and DAQ adapter boundary, including simulation mode.
- `sim_control/config_store.py` and `sim_control/models.py`: configuration loading, migrations, and dataclasses.
- `sim_control/waveform.py`: NI waveform building and line validation.
- `sim_control/pipeline.py`: reconstruction, feature, and decision placeholders.

## Current Project Facts

- The project is PyQt5-only today; `requirements.txt` contains `PyQt5`.
- `ui_sim_settings_dialog.py` is generated by PyQt5 UI code generator 5.15.11.
- SIM-side fourth red laser naming is `647`, not `640`.
- Default NI USB-6423 line map is `slm_enable=0`, `slm_trigger=1`, `slm_finish=2`, `camera_trigger=5`, `405=8`, `488=6`, `561=7`, `647=9`.
- Live preview should stay low-latency by showing the latest available frame and discarding stale intermediate frames.

## Testing Targets

- `tests/test_ui_regressions.py`: generated UI and SIM dialog geometry regressions.
- `tests/test_main_window_scroll_area.py`: legacy integrated window scroll wrapper behavior.
- `tests/test_sim_preview_restart.py`: live preview restart behavior.
- `tests/test_sim_daq_testing.py`: DAQ pulse/SIM acquisition test behavior.
- `tests/test_legacy_sim_config_migration.py`: legacy config migration including 640 to 647 compatibility.

## PyQt5 Review Checklist

- Imports remain `PyQt5`, not PyQt6 or PySide.
- Widgets are created and accessed only on the GUI thread.
- Workers emit signals; slots update UI state.
- Blocking SDK/DAQ/camera calls do not run in event handlers unless they are already known to be short and simulation-safe.
- Window close paths stop controllers and threads.
- Tests instantiate a single `QApplication` via `QApplication.instance()`.
- Headless or CI runs avoid depending on physical hardware.
